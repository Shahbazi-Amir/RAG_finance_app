**Scope:** [PROPOSED ADR 0003](../docs/adr/0003-history-persistence-proposal.md), [existing product.v1 HISTORY-01 contract](../packages/contracts/README.md) and [HISTORY-01 checkpoint](tasks/AGENT-HISTORY-01.md). These proposals do NOT authorize API implementation, PostgreSQL migration, RLS, a selected Auth provider, a runtime model call, Retention or any Module Gate.

- **H-DEC-01 (employer, Auth):** choose between (A, **recommended for evaluation**) managed standards-based OIDC Authorization Code+PKCE with server/BFF session or (B) first-party credentials + secure server sessions. Employer must approve privacy/data transfer, actual costs/vendor or engineering/MFA/recovery burden, credential handling, session revocation and post-account-deletion status access. **No fixed/anonymous Production identity.**
- **H-DEC-02 (API+DB):** approve create-conversation idempotency separate from send_message; original requested null vs allocated resolved conversation; status/error/HTTP routes and trace per attempt, 17→24 additive kinds; existing `product.v1` remains provisional pending consumer review.
- **H-DEC-03 (API+DB):** atomically persist T1 Receipt/Conversation/User Message, leave recoverable T1→T2 persisted gap; T2 Attempt + reserved_answer_id before permitted external call; T3 Assistant Message + Answer atomic commit. Recommend mandatory Receipt→Attempt for the send-message path, *not* generic internal attempts. No automatic model retry on Ambiguous/Unknown.
- **H-DEC-04 (legacy umbrella — retained for all existing references, NOT a second decision):** physical DB, concurrency, polling, cursor and privacy constraints are now separated into `H-DEC-04A`…`H-DEC-04F` below. `H-DEC-04` remains a valid backward-compatible reference to **all** children; it must not be counted twice. **Supervisor approved only the logical invariants for the first isolated synthetic PostgreSQL tests**; all production/SQL/Retention/Auth decisions require separate review.
  - **H-DEC-04A — owner-scoped uniqueness, nullable requested ID and concurrency (DB+API):** **TEST_BASELINE_APPROVED:** Create and Send have independent operation namespaces; concurrent Send with original `requested_conversation_id=null` must produce one Receipt/Conversation allocation/User Message, and same operation replay must not duplicate. **NEEDS_API_DB_REVIEW:** exact PostgreSQL version and `NULLS NOT DISTINCT`/partial index/canonical discriminator, locking/CAS, isolation, unique-violation response, multiple-owner and rollback tests. Plain nullable UNIQUE without tested NULL semantics is insufficient.
  - **H-DEC-04B — Send Receipt/Attempt single-entry boundary (API+DB):** **TEST_BASELINE_APPROVED:** one accepted Send/Receipt may have **zero or one** valid, linked Attempt in this first package. Network retry recovers, never inserts a second Attempt or runs the model. Existing prior multi-Attempt records are **preserved unchanged** and flagged as anomalies (fail closed on further scheduling); future multiple Attempts/engine re-execution are explicitly out of scope. **NEEDS_API_DB_REVIEW:** physical FK/UNIQUE, concurrent T2 safety, historical anomaly and versioned retry semantics.
  - **H-DEC-04C — server-only commit witness, coherent reads and Polling order (API+DB):** **TEST_BASELINE_APPROVED:** terminal outcome is established from trusted, owner-authorized durable Receipt+Attempt+Answer/assistant Message rows in a coherent read; never from client `server_commit_evidence`. Preserve historical T2 Trace versus current HTTP Poll Trace. **NEEDS_API_DB_REVIEW:** DB isolation/primary or replica policy, server monotonic revision/cursor of commit order, anomaly routing, and true cross-request consistency. A client-issued Poll sequence does **not** prove server commit order.
  - **H-DEC-04D — Create immutable creation snapshot and current authorization (API+DB):** **TEST_BASELINE_APPROVED:** replay is original creation snapshot, *not* mutable current Conversation data; current owner, access and nondeleted state must be revalidated before release. Foreign/deleted/inaccessible → indistinguishable generic **404**, no resurrection/no old title leak. **NEEDS_API_DB_REVIEW:** snapshot storage, row lock/access-vs-delete races, post-revocation behavior and physical deletion. Retention remains open.
  - **H-DEC-04E — cursor, owner isolation and enumeration (API+DB/security):** **TEST_BASELINE_APPROVED:** no cross-user enumeration, owner-bound cursor and generic 404 access policy. **NEEDS_API_DB_REVIEW:** real RLS/PK/FK joins, index plan, cursor HMAC key rotation/expiry, leak timing/metrics, actual Auth and adversarial tests.
  - **H-DEC-04F — TTL, Retention, Attempt leases and crash reconciliation (API+DB/employer):** T1/T2/T3 short-transaction boundaries are approved **for local synthetic test design**, but TTL/idempotency reuse horizon, rollback/lease/outbox scheduler, ambiguous provider outcomes, Retention/backup, hard deletion and real model re-execution remain **OPEN**. No model may be triggered by Recovery or Polling.
