# Foundation APP_ONLY live PG readiness invariant
The earlier APP_ONLY implementation preserved startup-PG admission but returned HTTP200 /health/ready after startup even if PG subsequently became unavailable. This is not actual readiness. Updated endpoint now requires a registered read-only live Product DB role/grant probe, runs it off the event loop with a bounded timeout, and returns 503 if it fails or wasn't installed. A source-level negative test simulates a PG outage; CI-only diag still returns Ready503. /health/live remains process-only. No Runner and no mutable DB action is performed by the probe. Signed actual SSL/PG target remains Ops-only.
