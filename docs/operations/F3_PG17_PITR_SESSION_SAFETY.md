# PG17 PITR and session safety — CI-only

Physical PostgreSQL recovery intentionally retains the database system identifier; it is isolated by distinct volumes and containers, unlike logical restore into a new system identifier. Run the candidate PITR workflow only on a disposable GitHub-hosted runner with network disabled and no published ports. It verifies a SHA256-manifest physical base, rejects modified backup bytes, archives WAL, restores to a named recovery point and checks owner-level rows, schema RLS and source immutability. Auth SQL uses synthetic identities only. A revoke before the point must remain revoked; a later revoke is naturally absent at that point. Therefore never expose a physical restore until the applicable approved revocation reconciliation policy is satisfied. The test reconciles the later synthetic revoke locally and never starts the app against the physical restore. No RPO/RTO, target authorization, engine or SQL011.
