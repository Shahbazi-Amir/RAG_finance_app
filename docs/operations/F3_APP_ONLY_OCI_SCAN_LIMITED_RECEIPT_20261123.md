# Foundation F3 APP_ONLY — direct OCI image inventory L1
A new separate matrix CI workflow scans **three actually built Docker images** API, Bootstrap, Web using a referenced Trivy Github action: CycloneDX SBOM + OS/library vulnerabilities in JSON plus a sanitized severity summary. Images are built with the exact source Git SHA label on ephemeral Ubuntu Linux/amd64 using DockerHub version-tag fallback because approved ECR registry returned 429 previously. They are NOT the reviewed immutable image release digests. The scanner runs only on built CI images; it does not read the original native Engine wheelhouse, Mac TLS PKI or eventual production ingress. A completed scan with HIGH/CRITICAL findings must be marked `REVIEW_REQUIRED_HIGH_CRITICAL_PRESENT`, **not vulnerability PASS**. `0 High/Critical` on this limited tag is only an L1 observation, not CENTRAL approval. Failed scanning or missing SBOM cannot be reported clean. Full production-image ABI, registry digest and source-approved vulnerability policy remain blocked. App-only execution, Mac and Arvan remain unchanged.

## First scanner setup failure and security fix
Initial [scan run 45264966898](https://github.com/Shahbazi-Amir/RAG_finance_app/actions/runs/45264966898) failed all three jobs at setup: action ref `aquasecurity/trivy-action@0.33.1` did not exist; **no scan executed**. The upstream verified v0.36.0 release commit is `ed142fd0673e97e23eac54620cfb913e5ce36c25`. New attempts pin this exact full 40-character commit rather than a mutable tag. This avoids compromised historical version tags. Scanner runtime uses only disposable CI images and a contents:read GitHub token, never Mac credentials or secrets. The scan is counted only if its exact-SHA jobs and JSON artifacts finish successfully.
