# BND-DB-03 — product PostgreSQL Service Assertion Replay Store

**Not Product Auth / BFF / real History wiring.** This DB-owned interface structurally implements the existing API \`ReplayStore.consume(conn,verified_proof)->bool\` Protocol from accepted PR #17. The DB does NOT authenticate BFF RSA signature, issuer identity or browser owner claims.

## Trusted API handoff and roles
Use \`src.phase3.storage.postgres.service_replay.PostgresDurableReplayStore\` with **auth_trust_api** connection: an autocommit PostgreSQL primary connection inside an explicit outer \`with conn.transaction():\`. Caller must supply a previously RSA-verified \`VerifiedServiceProof\` with \`issuer\`, \`jti\`, \`expires_at\`. In trusted Python memory, adapter computes **SHA256(issuer + NUL + jti)**; SQL receives **only digest plus signed exp epoch**, not raw JTI/JWT/Session/Cookie. API must not log these secrets. No public DTO added.

Required ordering (unchanged PR #17): validate RSA/claims/raw ASGI request bytes → outer transaction BEGIN → \`replay_store.consume(conn,proof)\` → exact-True \`auth_session.admit_session_fenced(conn,proof.session_ref,proof.owner_id,proof.epoch,proof.generation)\` → **API's existing final signed iat/nbf/exp/30s age recheck with fresh PostgreSQL clock after session locks** → protected SQL using same connection → COMMIT. If any step fails or returns non-True, rollback the entire transaction. A committed JTI is single-use. On rollback, JTI and action both disappear, but any retry still requires an UNEXPIRED proof. **Each separate network attempt must have a fresh random JTI**, even when the History message idempotency key remains unchanged; assertion replay and product message idempotency are different.

## DB response / limits
Migration \`005_service_assertion_replay\` adds \`auth_l1.service_assertion_replays(issuer_jti_sha256 PRIMARY KEY,expires_at,consumed_at)\`, FORCE RLS deny direct. Restricted \`SECURITY DEFINER\` routine \`auth_l1.consume_service_assertion(text,bigint)\` with fixed \`search_path=pg_catalog\` returns **exact True** on INSERT. Duplicate PK raises **\`psycopg.errors.UniqueViolation\`**, leaving outer PostgreSQL transaction ABORTED until ROLLBACK; never convert duplicate to a permissive boolean. Bad/NULL/negative input and expired or >30 seconds in the future get SQL rejection. PostgreSQL clock is checked before and **after** possibly-blocked unique INSERT. This does NOT replace API's post-session-lock final proof time check. No JWT signature verification in DB.

Only \`auth_trust_api\` has USAGE \`auth_l1\` + EXECUTE on the 005 consume routine and existing 004 \`admit_session_fenced\`. It has **no** direct replay/Session/Owner/History table access, issue/mapping/revoke/reauth, DDL, SUPERUSER or BYPASSRLS. SQL is owned by ephemeral CI \`auth_migrator\`, with privileged BYPASSRLS *only in disposable runner*; actual production SECURITY DEFINER owner/role provisioning needs separate review. A naked SQL call in autocommit commits and loses any transaction lock; the Python wrapper explicitly requires an open outer transaction. No API code was changed.

## Expiry cleanup
Optional **manual-only** \`cleanup_expired(conn,limit)\` uses separately restricted \`auth_replay_cleaner\` role with only EXECUTE on \`auth_l1.purge_expired_service_assertions(integer)\` plus schema USAGE. SQL enforces \`1<=limit<=1000\`, uses DB \`clock_timestamp()\`, only deletes rows with \`expires_at<=now\`, and skips locked rows. Never delete unexpired replay protection. No scheduled job, final retention policy or user data deletion. Once expired row is purged, stale proof remains forbidden due SQL time check and API final check; do not call purge proof of perpetual replay prevention for forged future timestamps. \`005.down\` destructively deletes replay rows on disposable CI DB only, not backup/restore.
